## 一、项目概览

### 1.1 项目定位

## 三、Android APK 自动打包方案

### 3.1 技术选型：Capacitor

选择 **Capacitor** 而非 Cordova/React Native 的理由：
- 与 Web 项目共享同一套代码，零额外开发量
- 官方维护，现代化 API 设计
- 支持 Android/iOS/Web 三端
- 轻量级，不侵入业务代码

### 3.2 配置要点

#### capacitor.config.ts

```typescript
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.jingfangjia.liuren',
  appName: '六壬占卜',
  webDir: 'dist',              // Vite 构建输出目录
  plugins: {
    SplashScreen: {
      launchShowDuration: 2000,
      launchAutoHide: true,
      backgroundColor: '#1a1a2e',
      showSpinner: false,
    },
  },
  server: {
    androidScheme: 'https',    // 使用 https scheme 避免 CORS 问题
  },
};
```

**关键点**：
- `webDir` 必须与 Vite 的 `build.outDir` 一致（默认 `dist`）
- `androidScheme: 'https'` 解决 WebView 中的混合内容限制
- `appId` 需与 Android 项目的 `namespace` 和 `applicationId` 一致

#### Android build.gradle 关键配置

```groovy
android {
    namespace = "com.jingfangjia.liuren"
    signingConfigs {
        release {
            storeFile file('release.keystore')
            storePassword 'liuren123'
            keyAlias 'liuren'
            keyPassword 'liuren123'
        }
    }
    defaultConfig {
        applicationId "com.jingfangjia.liuren"
        minSdkVersion 24
        targetSdkVersion 36
        versionCode 42       // 每次 Release 自增
        versionName "1.2.30" // 与 package.json 同步
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled false
        }
    }
}

// 自定义 APK 输出文件名
android.applicationVariants.all { variant ->
    variant.outputs.all { output ->
        def versionName = variant.versionName
        outputFileName = "liuren_v${versionName}.apk"
    }
}
```

**关键点**：
- `minSdkVersion 24`（Android 7.0）覆盖 99%+ 设备
- `targetSdkVersion 36` 满足 Google Play 最新要求
- 自定义 APK 文件名包含版本号，便于分发
- `minifyEnabled false` 避免 WebView 反射调用被混淆

#### variables.gradle 版本管理

```groovy
ext {
    minSdkVersion = 24
    compileSdkVersion = 36
    targetSdkVersion = 36
    androidxAppCompatVersion = '1.7.1'
    coreSplashScreenVersion = '1.2.0'
    // ... 其他依赖版本统一管理
}
```

### 3.3 签名密钥管理

#### 本地生成 Keystore

```bash
keytool -genkey -v -keystore release.keystore -alias liuren -keyalg RSA -keysize 2048 -validity 10000
```

#### GitHub Actions 中使用

1. 将 keystore 文件 Base64 编码后存入 GitHub Secrets：
   ```bash
   base64 -w 0 release.keystore > release.keystore.base64
   ```
2. 在 workflow 中解码还原：
   ```yaml
   - name: Decode keystore
     run: echo "${{ secrets.RELEASE_KEYSTORE_BASE64 }}" | base64 -d > android/app/release.keystore
   ```

3. `.gitignore` 中排除密钥文件：
   ```
   release.keystore
   release.keystore.base64
   .key/
   *.key
   *.key.pub
   ```

### 3.4 CI/CD 自动打包流程

```yaml
# .github/workflows/release.yml（Android 部分）
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'

      - name: Set up Java
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'

      - name: Install dependencies
        run: npm install

      - name: Auto bump version
        run: |
          CURRENT_VERSION=$(node -p "require('./package.json').version")
          IFS='.' read -r major minor patch <<< "$CURRENT_VERSION"
          NEW_VERSION="$major.$minor.$((patch + 1))"
          npm version --no-git-tag-version $NEW_VERSION
          # 同步 Android 版本号
          cd android
          NEW_VERSION_CODE=$(grep "versionCode" app/build.gradle | grep -o '[0-9]\+')
          NEW_VERSION_CODE=$((NEW_VERSION_CODE + 1))
          sed -i "s/versionCode [0-9]\+/versionCode $NEW_VERSION_CODE/" app/build.gradle
          sed -i "s/versionName \".*\"/versionName \"$NEW_VERSION\"/" app/build.gradle
          cd ..
          git add package.json android/app/build.gradle
          git commit -m "chore: auto bump version to $NEW_VERSION"
          git push https://x-access-token:${{ secrets.GITHUB_TOKEN }}@github.com/${{ github.repository }}.git

      - name: Build web
        run: npm run build

      - name: Sync to Android
        run: npx cap sync android

      - name: Decode keystore
        run: echo "${{ secrets.RELEASE_KEYSTORE_BASE64 }}" | base64 -d > android/app/release.keystore

      - name: Build APK
        run: cd android && ./gradlew assembleRelease

      - name: Create GitHub Release
        uses: softprops/action-gh-release@v1
        with:
          files: android/app/build/outputs/apk/release/liuren_*.apk
          tag_name: v${{ steps.get-version.outputs.version }}
```

**流程总结**：
1. `npm run build` → 构建前端到 `dist/`
2. `npx cap sync android` → 将 `dist/` 复制到 Android 项目
3. `./gradlew assembleRelease` → 编译签名 APK
4. `softprops/action-gh-release` → 上传 APK 到 GitHub Release

### 4.6 前端自动更新实现

#### 检测 Tauri 环境

```typescript
const isTauri = () => '__TAURI__' in window || '__TAURI_INTERNALS__' in window;
```

#### 自动更新 Hook（useTauriUpdater.ts）

```typescript
import { useState, useEffect } from 'react';

export function useTauriUpdater() {
  const [updateAvailable, setUpdateAvailable] = useState(false);
  const [updateInfo, setUpdateInfo] = useState(null);
  const [downloading, setDownloading] = useState(false);

  const checkForUpdate = async () => {
    if (!isTauri()) return;
    const { check } = await import('@tauri-apps/plugin-updater');
    const update = await check();
    if (update) {
      setUpdateInfo({ version: update.version, date: update.date, body: update.body });
      setUpdateAvailable(true);
    }
  };

  const downloadAndInstall = async () => {
    const { check } = await import('@tauri-apps/plugin-updater');
    const update = await check();
    if (update) {
      await update.downloadAndInstall(() => {});
      await window.__TAURI__.process.relaunch();
    }
  };

  useEffect(() => {
    checkForUpdate();
    const interval = setInterval(checkForUpdate, 4 * 60 * 60 * 1000); // 每4小时检查
    return () => clearInterval(interval);
  }, []);

  return { updateAvailable, updateInfo, downloading, checkForUpdate, downloadAndInstall };
}
```

## 六、版本管理与自动发布

### 6.1 版本号策略

- **单一版本源**：`package.json` 中的 `version` 为唯一版本号来源
- **Tauri 同步**：`tauri.conf.json` 中 `"version": "../package.json"` 自动读取
- **Android 同步**：CI 中通过 `sed` 命令将版本号写入 `build.gradle`

### 6.2 自动版本递增

```bash
# 读取当前版本
CURRENT_VERSION=$(node -p "require('./package.json').version")
# patch +1
IFS='.' read -r major minor patch <<< "$CURRENT_VERSION"
NEW_VERSION="$major.$minor.$((patch + 1))"
# 更新 package.json
npm version --no-git-tag-version $NEW_VERSION
# 更新 Android build.gradle
cd android
NEW_VERSION_CODE=$(grep "versionCode" app/build.gradle | grep -o '[0-9]\+')
NEW_VERSION_CODE=$((NEW_VERSION_CODE + 1))
sed -i "s/versionCode [0-9]\+/versionCode $NEW_VERSION_CODE/" app/build.gradle
sed -i "s/versionName \".*\"/versionName \"$NEW_VERSION\"/" app/build.gradle
```

```bash
  RELEASE_NOTES=$(git log $LAST_TAG..HEAD --pretty=format:"- %s" --grep="^(feat|fix|refactor|docs|perf)")
else
  RELEASE_NOTES=$(git log --pretty=format:"- %s" --grep="^(feat|fix|refactor|docs|perf)")
fi
```

## 八、项目遇到的报错及解决方法

### 8.1 Android 相关

#### 问题1：Capacitor sync 后 Android 项目编译失败

**现象**：`npx cap sync android` 后 Gradle 编译报错找不到 Capacitor 依赖

**原因**：Capacitor 插件未正确链接到 Android 项目

**解决**：
```bash
npx cap sync android    # 确保先执行 sync
cd android
./gradlew clean         # 清理缓存
./gradlew assembleDebug # 重新编译
```

#### 问题2：Android WebView 混合内容被阻止

**现象**：Android 9+ 设备上 HTTP 请求被阻止

**原因**：Android 默认禁止明文 HTTP 流量

**解决**：在 `capacitor.config.ts` 中设置 `androidScheme: 'https'`

#### 问题3：APK 签名不一致无法覆盖安装

**现象**：新 APK 安装时提示签名不一致

**原因**：Debug 签名和 Release 签名不同

**解决**：始终使用同一 keystore 签名，keystore 备份到安全位置

#### 问题4：Gradle 版本不兼容

**现象**：`Could not find com.android.tools.build:gradle:X.X.X`

**原因**：Gradle 插件版本与 Gradle Wrapper 版本不匹配

**解决**：确保 `android/build.gradle` 中的 `classpath` 版本与 `gradle-wrapper.properties` 中的 `distributionUrl` 版本兼容

### 8.2 Tauri/Windows 相关

#### 问题5：Tauri 构建时 Rust 编译失败

**现象**：`npm run tauri:build` 报 Rust 编译错误

**原因**：Rust 工具链未安装或版本不兼容

**解决**：
```bash
# 安装 Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# 更新到稳定版
rustup update stable
```

#### 问题6：Tauri 窗口白屏闪烁

**现象**：应用启动时短暂白屏

**原因**：前端资源加载需要时间，窗口在加载完成前已显示

**解决**：
1. `tauri.conf.json` 中设置 `visible: false`
2. Rust 代码中 `setup` 回调里调用 `window.show()`

```rust
.setup(|app| {
    let window = app.get_webview_window("main").unwrap();
    window.show().unwrap();
    Ok(())
})
```

#### 问题7：Tauri 自动更新签名验证失败

**现象**：更新下载后提示签名无效

**原因**：构建时未设置签名密钥环境变量

**解决**：
```yaml
env:
  TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_PRIVATE_KEY }}
  TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_KEY_PASSWORD }}
```

#### 问题8：NSIS 安装器显示英文

**现象**：安装界面默认显示英文

**原因**：未配置中文语言文件

**解决**：创建 `nsis-simpchinese.nsh` 并在 `tauri.conf.json` 中引用：
```json
"windows": {
  "nsis": {
    "displayLanguageSelector": true,
    "languages": ["SimpChinese", "English"],
    "customLanguageFiles": {
      "SimpChinese": "../nsis-simpchinese.nsh"
    }
  }
}
```

### 8.3 前端/构建相关

#### 问题9：Vite 构建时路径别名不生效

**现象**：`@/xxx` 导入路径 TypeScript 识别但 Vite 构建报错

**原因**：Vite 不读取 `tsconfig.json` 的 `paths` 配置

**解决**：安装 `vite-tsconfig-paths` 插件：
```typescript
// vite.config.ts
import tsconfigPaths from "vite-tsconfig-paths";
export default defineConfig({
  plugins: [react(), tsconfigPaths()]
});
```

#### 问题10：GitHub Actions 推送版本号提交失败

**现象**：`git push` 报 403 权限错误

**原因**：`actions/checkout` 默认的 `GITHUB_TOKEN` 权限不足

**解决**：
1. 使用 `persist-credentials: false`
2. 推送时使用带 token 的 URL：
```bash
git push https://x-access-token:${{ secrets.GITHUB_TOKEN }}@github.com/${{ github.repository }}.git
```
3. 确保 job 有 `permissions: contents: write`

#### 问题11：GitHub API 速率限制

**现象**：Web 端检查更新时频繁返回 403

**原因**：GitHub API 未认证请求限制 60次/小时

**解决**：在 `UpdateChecker.tsx` 中实现缓存策略：
```typescript
const lastCheck = localStorage.getItem('liuren_last_update_check');
const now = Date.now();
if (!lastCheck || now - parseInt(lastCheck) > 4 * 60 * 60 * 1000) {
  checkUpdate();
  localStorage.setItem('liuren_last_update_check', now.toString());
} else {
  // 使用缓存的版本信息
}
```

#### 问题12：Capacitor Android 项目中 APK 输出文件名未自定义

**现象**：默认输出 `app-release.apk`，不包含版本号

**解决**：在 `android/app/build.gradle` 中添加：
```groovy
android.applicationVariants.all { variant ->
    variant.outputs.all { output ->
        def versionName = variant.versionName
        outputFileName = "liuren_v${versionName}.apk"
    }
}
```

### 9.1 架构设计

采用**用户自带 API Key** 模式，避免服务端成本：

- API Key 存储在浏览器 localStorage

### 9.2 流式输出实现

```typescript
const response = await fetch(`${config.baseUrl}/chat/completions`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${config.apiKey}`,
  },
  body: JSON.stringify({
    model: config.model,
    messages: [{ role: 'user', content: fullPrompt }],
    stream: true,
  }),
  signal: abortController.signal,
});

const reader = response.body?.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop() || '';
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const data = line.slice(6);
      if (data === '[DONE]') break;
      const parsed = JSON.parse(data);
      const content = parsed.choices?.[0]?.delta?.content;
      if (content) setAiResponse(prev => prev + content);
    }
  }
}
```
